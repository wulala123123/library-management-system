# 阶段 3 完善图书和逐册管理

阶段标识：MBA-03。依赖与总体完成标准见[项目路线](../../../../PROJECT.md)，执行游标见[当前工作](../../../../PLAN.md)。

- [ ] B30 明确两层记录：图书资料按书目管理；每本实体书按馆内条码管理。新增库存时登记对应实体册，默认新增数量建议为一册。
- [ ] B31 补齐条码登记、批量新增、查询、位置调整、停用与报损流程。条码唯一且保留前导零；已借出的册不能直接删除或改为可借。
- [ ] B32 采购入库、手工补录、报损和盘点统一维护实体册、汇总库存与变更流水。采购重复入库或请求重试不能重复增加册数。
- [ ] B33 图书表单与筛选增加适读年龄、装帧等有来源的属性。自定义书名作为展示名称保留，同时保留原书名。
- [ ] B34 建立套装与单册的关联，保留每册身份。仅有“套装中单本”标记而缺少明确归属时，进入待核实清单，核实后再建立关系。
- [ ] B35 建立分类与出版社资料，关联现有图书。年龄标签与主题分类分别管理；出版社同名先规范核对，名称相近的记录列为待确认。
- [ ] B36 统一书目位置、逐册位置和书架库位的使用方式，以逐册实际位置为准；原位置为空的实体册保留未分配。出版信息和简介另列补录任务，批量补录提供预览和来源。

验收：每笔新增实体库存均能查到对应册及条码；逐册状态与总库存一致；同一书目的多册可分别借还、放置和追溯。

## 实施分批

先提供书目与实体册两层查询、条码精确查找、状态/位置筛选及登记差额，只读且不补造历史册。随后统一手工和采购新增入库的册、汇总及流水事务，关闭单改汇总的旧增量旁路；逐册库位和状态动作单独接入。

B30/B31 的查询子范围已实现、完整验收并以 `88dc996` 上线，见[当次验收](../../../archive/2026-10/catalog-query-2026-10-15.md)：管理员和馆员可分别查看书目登记差额、实体册列表和必要在借关联；精确条码按完整 UTF-8 字节匹配，空册位置显示未分配。书目与册的总数、可借数、在借数及汇总平衡差额仅作为核对线索，不自动补造册或修库存。现有 `/books/{id}/copies` 数组契约保留，读者不能访问管理查询。

后端 H2 11 项、真实 MySQL 1 项及前端 5 项通过，类型构建和合成浏览器通过；经理验收证据为私有 `logs/catalog-stage3/query-manager-acceptance.json`。完整任务仍待登记、入库和状态流程完成，不以查询交付勾选整个 B30/B31。

用户已确认临时停用计总库存但不可借，正式报损扣总库存，恢复须独立登记并审计；已借册须先归还。该规则须经实现与验证后启用，当前查询不改变库存口径。

## 下一批入库边界

当前图书新增、编辑库存和采购快速入库仍主要写汇总，尚未逐册登记。下一批需统一为实体册、汇总增量与来源流水同事务提交，手工和采购重试不重复加册；书目资料编辑不再直接改变库存。历史登记差额继续保留待核实，不用自动造册补平。

新增条码取得方式已确认：优先录入已贴条码；无条码时生成独立馆内码，预览确认后用于贴标。书目 ISBN 不作为馆内条码，原字符串条码保留。该能力在下一批实现并验证后启用。

入库方案已由经理验收并开始实现，当前固定契约为预览/确认/按幂等键查回执，以及独立 metadata 摘要与显式字段变更。默认 1 册，生成码仅在成功回执后可打印，采购可按待收量分批；同一后端 owner 统一手工、采购及旧旁路，前端独立接入。V8 预计新增请求/逐册来源表和精确条码键，尚未验证或上线；回退安排必须冻结旧汇总入库入口。
