# 第一批来源字段与权益核对

适用范围：阶段 0 的字段核对和第一批 B10–B14。以下是来源语义及实施边界，未接入的字段不表示已经提供办理能力。

## 核对依据

原迁入批次、官方 XLSX、页面快照及源文件 SHA256 清单相互校验；会员原始档案与 `member_profile` 按来源 UID 关联。私有目录 `logs/member-business-batch1/` 和服务器 `migrations/member-business-batch1/` 保存逐字段覆盖情况、实际权益和核对结果。真实身份、日期明细、套餐金额及备份内容不进入公开文档。

状态含义：日常业务字段为已承接到业务表的事实；原始存档为保留但尚未接入日常办理；源资料为空不补造；待核实只影响依赖该语义的操作；人工补充须有独立来源和修订记录。

## 会员字段

| 来源字段 | 承接位置及分类 | 第一批处理 |
| --- | --- | --- |
| 来源 UID、登录账号、姓名、手机号 | `sys_user`、`member_profile.source_key`；日常身份 | 来源 UID 独立，不因共享手机号合并；列表序号不改变身份 |
| 卡号 | `member_profile.card_no`；日常业务字段或源资料为空 | 空白显示未设置，不以 UID 或数据库主键代替 |
| 借阅计划类型 | `member_profile.plan_name`；日常业务字段 | 保留来源名称，不直接把当前套餐默认值套到老会员 |
| 服务开始时间、服务结束时间 | `member_profile.service_start/service_end`；日常业务字段 | 原实际起止日优先；缺失单列待核实，不计算替代日期 |
| 已借阅次数 | `member_profile.used_uses`；原累计事实 | 保留原累计，不能用导入的借还册明细重算订单次数 |
| 总次数及页面总次数标签 | `member_profile.total_uses`；日常业务字段，存在映射错误 | 明确不限才映射 NULL；有限及真正零次数原样保留；未知拒绝推断 |
| 实际缴纳费用、实际缴纳押金 | `paid_fee/deposit_amount`；来源金额事实 | 原值保留，不能当作当前应收或可退余额 |
| 缴费状态、押金缴纳状态、押金退还状态 | 业务摘要及会员原始存档 | 分别核对，不能只根据曾缴金额判断仍有余额 |
| 会员昵称、地址、推荐人、备注 | 会员 `legacy_record.details_json`；原始存档 | 后续会员档案接入；不把空备注改成猜测内容 |
| 宝宝及二宝、三宝名字、生日、年龄、性别 | 会员原始存档；原始存档或源资料为空 | 保留多名宝宝及原精度，后续按权限接入，不由年龄反推生日 |
| 注册时间、入会时间、入会天数、剩余天数 | 原始存档；历史快照 | 动态天数不是新的起止日依据，不覆盖会员实际日期 |
| 书箱、书箱价格、配送日、未还统计 | 原始存档；待核实办理语义 | 不触发收费、出库或改动在借记录 |
| 原系统补充资料 | 原始存档 | 原文保留，不依据展示文本自动修改身份或权益 |

## 书目、实体册及借还字段

| 来源字段 | 承接位置及分类 | 第一批处理 |
| --- | --- | --- |
| ISBN / 内部书号、书籍名称、作者、出版社 | `book`；日常业务字段 | 书目与实体册分别计数；同 ISBN 元数据冲突须核实 |
| 馆内编码 | `book_copy.barcode`；实体册身份 | 字符串保存，保留前导零 |
| 购买数量、库存、是否外借、书籍状态 | 汇总库存、实体册状态及原始存档 | 与未还记录共同核对；统计显示汇总与逐册差异，不自动改库存 |
| 书架位置、书位号 | `book_copy.location` 及原始存档；业务字段或源资料为空 | 缺失显示未设置；书目未登记库位也不猜填 |
| 出版日期、页数、简介 | 当前来源没有提供可确认业务值；源资料为空 / 人工补充 | 显示待补充；已知值含零原样保留 |
| 适读年龄、套装类型、装帧、自定义书名 | 实体册原始存档 | 后续图书阶段接入；不凭 ISBN 推断套装关系 |
| 精装价格、平装价格、实际原价、购入价格、自定义价格、购书来源 | 来源存档及原迁入价格映射 | 保留来源类别，不把不同价格解释成同一种收入 |
| 累计借阅次数 | 来源累计存档 | 不与已覆盖明细相加，不替代订单次数 |
| 录入时间、原书籍信息、封面原地址 | 原始存档与封面文件 | 保留源精度及原封面字节 |
| 借出、归还时刻、来源借阅键、会员、条码 | `borrow_record` 及原始存档 | 原关联不变；完整时刻与业务日期分别保留 |
| 不限制应还日期 / 来源未提供日期 | `due_date_kind=UNLIMITED/UNKNOWN` | 分别显示；不推导默认应还日 |
| 原订单状态、内容与费用 | `legacy_record` 的 ORDER | 历史查询，不重新出库、收款或扣次 |

## 套餐与个别权益

原套餐页面设置、会员所选计划、会员实际起止日及已用次数分别保留。私有权益核对记录包含每名会员的来源键、实际日期、原套餐设置及可疑差异；差异是人工核实候选，不自动断定调整原因。

套餐服务天数与实际日期的比较须区分是否包含首尾日，不能直接用日期差覆盖实际权益。会员已使用的次数和原系统逐册借还数量属于不同统计对象。本批只修正来源明确不限的总次数，其他权益、金额和历史资料保持原值。

## 零值与办理示例

- 合成例：导出总次数为 0，页面明确“总：不限次数”，可映射为不限；只有导出的 0 或页面仅“剩余：不限”不能成为不限依据。
- 合成例：总次数为 0 且没有明确不限来源，保留 0；总次数为 12 保留 12；空白或未知不能映射成不限。
- 原套餐帮助文字对总次数的 0 有专门解释；借阅周期、续借次数、金额、库存的 0 不继承该解释。未核实字段继续留在原始存档。
- 合成例：会员实际服务至 12 月 20 日，套餐默认期限算出 12 月 1 日，继续保留 12 月 20 日并记录差异，不重算覆盖。

已确认的后续会员规则见[账号和会员规范](../../specs/membership.md)，未决选项及阶段状态见[阶段 0](stages/00-baseline.md)。
