## 验证与交付

沿用[测试与发布检查](../../development/testing.md)，按实际改动补验证，复用未改部分的有效证据，不增加历次全量业务重验。

- 文件归档和文档批次：核对引用、必要文件哈希及归档可读性，运行文档与差异检查。
- 测试产物治理：运行受影响的真实隔离上传检查，保持原大小/类型/权限断言，核对成功或失败结束后的临时产物回收。
- 前端批次：类型检查、构建及相关组件/API用例；共享权限或恢复逻辑变化时覆盖对应拒绝和迟到响应。
- 后端批次：编译及实际影响的CSV/接口/事务等定向检查；涉及数据库并发或事务时使用合成隔离数据库。
- 打包和容器工具变化：保留原流程与五轮门槛，核对实际包内输入；不能通过更新冻结哈希放过范围外修改。
- 正式发布前仍须目标提交完整Verify及既有发布要求；只做本地清理的批次不为此触发生产发布。

每批交付实际移除/归档/合并清单、工作目录和构建包前后大小、验证结果、剩余项及是否上线。完成约定目标且必要检查通过后即交付；无证据支持的重构不继续扩展。
