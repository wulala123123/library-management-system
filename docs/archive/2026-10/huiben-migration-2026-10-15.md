# 绘本馆数据迁移

> 历史记录：正文中的状态、版本和验收结论适用于记录当时。当前项目状态见 [PROJECT](../../../PROJECT.md)，现行规范见[文档中心](../../README.md)。

## 范围与原始数据核对

用户选择完整迁移图书、会员、借阅历史，并保留会员卡期限、押金等信息。源站为已登录的 `houtai.huiben.cn`，目标为用户自有的 `library.webuihub.com`。

源站导出与页面详情交叉核对后，私有 `reconciliation.json` 记录图书种数、实体册数、可借库存、未还数量、会员、借还明细、订单、借阅计划、封面及实缴押金合计。真实业务数量和财务数据不写入公开代码仓库。

图书、会员和未还清单使用源站官方 XLSX 导出。借还明细按会员分别导出；无借阅记录的会员也要核对。另保存全部订单详情、会员补充资料、计划设置以及每本书的页面条码、套装关联和封面地址。封面按源站列表提供的缩略图原字节保存到自有上传卷。

原始文件、密码散列、准备结果和校验报告属于私有运行数据，存放在被 Git 忽略的迁移目录及服务器权限 700 的迁移目录。不会进入 Git、CI 或发布包。CI 仅使用合成数据。

## 数据承接方式

- 图书仍按原 ISBN / 内部书号归类；`book_copy` 单独保留每本书的馆内条码及在借状态。相同 ISBN 的实体册不会丢失。
- 馆内条码可搜索图书和借阅记录，办理借阅时可指定实体册，也可自动分配可借册。借阅、归还在同一事务内同时维护实体册状态与总库存。
- 原系统标明“不限制”归还日期的记录按 `UNLIMITED` 保留，不补造应还日期。历史已归还记录没有提供应还日期时，按 `UNKNOWN` 保留。
- 原借出、归还的完整时分秒保存在借阅备注及原始资料，业务日期列保留对应日期。
- 会员按源站 UID 建立新读者账号，不按手机号合并。共享手机号的家庭成员仍分别保留。
- `member_profile` 保留原卡号、计划、服务起止日、次数、实际缴费及押金。不限次数保留为不限，押金缴纳与退还状态分别保留在原资料。
- 管理员“原系统资料”页可查会员权益、每册原始资料、完整订单和借阅计划。读者、图书管理员均不能读取该资料页的财务与个人信息接口。
- 原系统密码无法导出，新账号使用独立随机密码的 BCrypt 散列初始化，明文不保存。需要读者登录时，由管理员分别设置或重置密码。
- 原会员卡及计划资料用于核对原权益；新办理的借阅执行当前系统规则。小程序身份、支付商户、自动续费及外部绑定不随表格数据迁移，需要按各平台的账号权限另行配置。

## 导入与保护

`prepare_huiben_migration.py` 只准备数据并校验：图书页与导出条码集合、每名会员已借册数、未还清单与历史明细、出库时刻、库存和订单关联均必须一致。源文件生成 SHA-256 清单。

`apply_huiben_migration.py` 默认只生成 SQL 预览。正式执行要求：

1. 目标已完成 V4 数据库升级。
2. 源文件校验值等于审核的快照。
3. 完成完整 CI、独立临时数据库试导入和数量核对。
4. 核对旧系统在快照后是否新增业务，安排最终切换。
5. 完整数据库、上传文件、环境和版本备份的 SHA-256 均通过。
6. 停止图书馆前后端后再执行正式导入，避免与在线业务并发写入。

导入在一个事务内执行。现有同 ISBN 的书必须先通过书名、作者、出版社冲突检查，才可追加库存；不覆盖原账号和历史。事务内校验不通过即中止并回滚。相同批次已经成功执行时返回已导入，重复 SQL 会被批次键和来源键阻止。

导入后逐行核对迁移前已有用户、借阅、罚款、分类及图书。除已确认同 ISBN 的库存增加外，原记录必须保持原值。若需回退到旧版本，应恢复切换前的完整备份，不能仅换回旧代码后继续处理导入记录。
