## 依赖变更与剩余告警

后端升级 Spring Boot 至 3.5.16、JJWT 至 0.13.0，并覆盖 Jackson 2.21.7、Tomcat 10.1.61、Log4j 2.25.5 和 Commons Lang 3.18.0。移除没有业务引用的 Hutool，连接池改为 Spring Boot 默认 Hikari。前端使用 Node 24.19.0、pnpm 11.25.0、Vite 7.3.7、TypeScript 5.9.3、Vue 3.5.43、Axios 1.20.0 等锁定版本。

剩余两条告警为 Spring Framework 6.2.19 的 CVE-2026-47890 和 CVE-2026-47884。前者需要通过 SSE 发送视图片段，后者需要使用 XsltView 并满足隐式视图路径条件。官方将两者分别评为 LOW 和 MEDIUM；6.2.20 修复版本需要企业支持，公开修复分支为 7.0.9。[SSE 官方说明](https://spring.io/security/cve-2026-47890/)、[XsltView 官方说明](https://spring.io/security/cve-2026-47884/)。

对本项目“不满足触发条件”的判断来自源码检查：应用使用 JSON REST 控制器，没有 SSE 视图片段或 XsltView。该判断属于使用路径评估，不能称为依赖版本已修复。审计脚本保留这两条记录，若源码引入相关特性则不再认可当前评估，并阻断 CI。后续开发如增加服务端视图、SSE，须先升级相应框架并重新测试。

前端主包仍约 1.1MB，构建提示大包警告，功能验证不受影响；可以在后续性能工作中按页面拆分依赖。本轮未宣称完成性能或负载容量验收。

## 剩余发布门槛

隔离 Docker 验收已通过。服务器上线前仍需核对实际端口、网络、代理 IP、域名和独立密钥；若接管真实旧库，先停写备份，在隔离环境检查真实结构和上传目录。CI 的旧库用例覆盖仓库原 SQL，不等于认可额外定制的业务库结构。回退演练使用同一安全版本的有效 JAR 与故障 JAR，验证运维机制，不承诺未来不兼容迁移可自动回退。

业务规则已采用：生成码不预留库存，核销时借阅；同 ISBN 元数据冲突要求人工核对；资源限额 50MiB。3 张历史头像原字节整理到 `legacy-data/uploads/`，停止 Git 跟踪运行目录，本机原文件保留；归档及运行数据均不随发布包分发。旧环境升级应迁移完整真实上传目录。

部署时间、域名和服务器系统维护继续留在后续部署任务。执行步骤见 [部署文档](../../operations/deployment.md)，数据库接管见 [迁移文档](../../operations/database-migrations.md)。
