# 发布验证与维护时间

本页规定后续发布的验证范围、证据复用和维护时间控制。操作步骤及版本兼容限制见[部署与恢复](deployment.md)，完整 CI 门槛见[测试与发布检查](../development/testing.md)。

各发布阶段同样遵循[验证职责、证据复用与结束条件](../development/testing.md)。本页补充发布现场要求；不能以“发布验收”为由自动重做全部历史功能检查。

## 适用边界

本规则用于新批次及重新审查后的发布编排。已启动任务的准确工具、一次性批准和证据保持原样；调整在途任务时先确认进程及实际数据库版本，由原执行者安全收尾。文档变更不构成已运行阶段通过，也不直接修改其验收标准。

历史专项流程中的数据兼容、旧写入口风险和恢复限制继续适用。历史逐书 HTTP 清单按本批影响重新选择；复用旧工具前先审查范围和实际耗时，不把历次全部接口检查自动叠加到新批次。

## 验证安排

| 内容 | 执行位置与完成标准 |
| --- | --- |
| 业务正确性 | 在 CI 和隔离环境覆盖本批事务、权限、重试、并发、失败回滚及容器生命周期；生产使用目标提交完整 Verify 的验收产物 |
| 真实数据保留 | 每份恢复备份和实际升级边界完整核对旧表值、结构、序列、历史关联及已审迁移增量；不能用接口抽样替代数据保全 |
| 接口兼容 | 停服前在隔离环境完成本批相关完整回归；未改模块按角色、空/非空、分页和特殊值选择代表场景，记录选择依据 |
| 正式切换 | 完整备份、准确候选安装与迁移、数据保全、运行字节、健康、关键接口和页面检查；生产仅只读验收，不造业务样例 |
| 环境身份 | 在明确阶段边界核验目标、资源归属和漂移；逐请求检查如有必要须计入总预算，优化读取方式须先独立验证 |

影响范围包括共享鉴权、序列化、查询、数据库和依赖变化。涉及共享代码时扩大相关回归；不能仅以页面未改为由省略。相同输入下已通过的有效证据直接复用，明确候选、配置、来源和仍然适用的条件；条件变化时只补受影响的验证。

已有专项流程明确要求两份最新独立备份时，该门槛保持；其他批次按变更风险及适用部署规范确定恢复演练，不因历史批次做过两轮而自动增加。要求两轮的批次分别证明备份可恢复及升级数据正确；各轮接口检查说明本轮独有风险和复用依据，避免机械重复全站逐书查询。新编排须验证失败、重试、断线与资源清理后才能用于生产。

## 停服前必须完成的准备

执行者在当前活动计划记录下表；原始清单和响应留在私有证据目录，不另外建立员工台账。

| 项目 | 必填内容 |
| --- | --- |
| 发布目标 | 变更范围、准确提交、完整 Verify、产物及校验文件 |
| 阶段清单 | 每阶段验证项、风险依据、执行位置、复用证据及完成条件 |
| 实际工作量 | 按当前数据规模枚举请求数、角色、分页、逐实体循环、环境读取次数和证据空间；合成规模不能代替真实规模估算 |
| 实测耗时 | 在安全的隔离环境测主要路径，计入备份/恢复、数据比较、构建、安装和验收；预构建及长回归在停服前完成 |
| 维护预算 | 停服开始点、总时长上限、各阶段预计时长、恢复服务所需时间和缓冲 |
| 退出路径 | 未迁移、已迁移两种现场的停止条件、数据兼容依据及可执行恢复或前向修复入口 |

维护预算必须覆盖已测切换耗时、恢复服务时间及缓冲。默认单次维护上限为 30 分钟；用户明确的窗口优先。无法在预算内完成时先调整隔离验证或发布编排，完成验证后再安排发布；确需更长停机时先说明具体时长和营业影响，由用户确定窗口。不得把“核验通过即可发布”理解为无限期停服。

第一轮耗时恢复演练优先安排在营业期间的隔离环境：通过短暂停写取得一致备份，确认恢复原应用安全后先恢复营业，再验证隔离副本。最终备份及正式迁移才进入持续停写。具体备份一致性、恢复旧应用安全性和两个快照之间的业务增量必须由本批方案证明；旧专项编排不能直接套用此安排。

停服前准确工具在目标 Linux 完成装配和运行验证，退出路径同样具备可用入口。工具缺陷、版本不匹配或主要路径耗时未测清时继续准备，保持原服务。

## 执行中的时间控制

1. 每阶段记录总量、完成量、实测速度和剩余时间，区分当前阶段与整次发布。仅有累计响应数不能作为完成比例。
2. 预计下一阶段会超过剩余预算时停止启动新阶段，执行已经验证的服务恢复路径。不要在长期维护状态中继续开发发布工具或重跑全套资格。
3. 未发生生产迁移且完整核对证明原应用安全时，受控恢复准确原版本；生产已迁移或兼容性不明时保留数据库及新业务，按已审方案前向修复。超时不授权强杀迁移、回灌旧备或启动不兼容旧代码。
4. 本地等待超时先读取同一远端任务状态和终态回执，不重复启动或消费旧批准。中断后保存原结果和恢复位置。
5. 进度在阶段完成、预计时间明显变化或需要用户决定时说明，并遵守当前聊天的沟通要求。交付分别说明验证、应用版本和营业状态。

## 工具维护与收尾

发布工具的通用部分逐步纳入仓库和 CI，使用合成数据覆盖边界、规模、断线续查及失败恢复；真实备份、凭据和原始业务响应继续保留在受保护位置。私有一次性脚本不能在缺少独立验证时充当后续批次的通用框架。

每批收尾只把仍适用的通用规则写回规范，阶段结果进入档案。新增检查须说明防范的风险、执行阶段及时间成本；替换已有检查须给出覆盖依据。验证范围和退出条件在停服前固定，避免在运行期间不断增加完成门槛。
