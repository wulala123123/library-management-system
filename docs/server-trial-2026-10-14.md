## 访问和凭据

从有 `sub2api` SSH 配置的本机运行：

```powershell
ssh -N -L 127.0.0.1:18080:127.0.0.1:18080 sub2api
```

隧道运行期间访问 `http://127.0.0.1:18080`。若本机端口已占用，应先核对占用者，不停止未知进程。

管理员用户名 `admin`。初始密码在服务器 `.env` 的 `ADMIN_PASSWORD` 中，仅通过有权限的 SSH 会话读取。登录后修改管理员密码；这不会修改 `.env` 中已失效的首次引导值，应用重启不覆盖账号密码。不要公开整个环境文件。

公网域名、代理接入、TLS 和真实旧库迁移继续留在后续发布步骤。使用实际域名前须同步 CORS、核对代理 IP 和外部网络，再安排发布。

## 现场追加检查

首次安装三个容器健康，V1–V3 迁移全部成功；实际验证码管理员登录、14 个模块查询、匿名用户管理拒绝、验证码重放拒绝通过。空库只有 1 名管理员，无图书、借阅或采购测试数据。首份数据库、上传文件和环境备份已生成，备份后应用恢复健康。

前端 JS 返回 403：操作员使用 `umask 077` 时，ZIP 未显式记录的目录按 700 创建，Docker COPY 后 Nginx 工作进程不能遍历 `assets` 目录。原 CI 只验证首页和 API，未加载首页引用的实际资源，未发现该问题。新增解压时独立 `umask 022`，不改变 `.env` 的 600 权限；容器验收从严格 umask 首次安装，并查询每个首页引用的 JS/CSS；运维用例补充目录权限检查。CI 版本名改用源码 SHA，避免后续更新与不可覆盖的旧 `ci` 版本目录冲突。修复后须先通过完整 CI，再更新服务器。

已核对所有部署前运行容器的 ID、启动时间、重启次数未变化。图书馆三个容器只加入 `library_app` 网络；仅前端绑定 `127.0.0.1:18080`。新服务占用约 640MiB 内存，服务器仍可用约 2.1GB。原有 root 文件和私人配置未写入仓库。
