# Codex 会话适配

首次操作员工会话、身份不明或需要修订时读。工具 schema 与实际返回决定能力。

## 派发

用户指派经理、授权联系具体员工、授权创建新会话是不同授权；已有明确授权无需重复询问。
讨论技能不构成业务派单授权，员工身份也不授权它主动给其他会话发消息。

当前任务的实施子任务优先使用子代理；复用原员工时用`followup_task`，不新建长期会话。
子代理通过最终输出回传，使用`wait_agent`等待完成；不要对它使用独立会话的消息工具。

已有长期员工会话按以下方式接入：

1. 从现有活动索引取得员工身份；首次或身份不明时用 `list_threads` 核对实际标题、threadId、
   hostId。只在恢复确有缺口时 `read_thread`，不读取完整过程史。
2. 在现有索引保留任务版本、执行者和交付入口，向已授权员工用 `send_message_to_thread`
   发完整任务。新任务正文与支持的 `model` / `thinking` 参数使用同一具体配置。
   状态、停止、补证消息省略这些参数，保留在途设置。
3. 派发结果明确后进入同轮等待，无需另索取接单报告。
   结果未知时只核对是否收到该版本；不能直接重复发送或另建执行者。

只在用户明确要求新会话或已允许按需创建员工时用 `create_thread`；
先 `list_projects`，默认项目本地环境，用户要求 worktree 时才选 worktree。
同步传入具体配置和任务上下文，不发明分支，不假定未提交文件随新树复制。
clientThreadId 只表示准备中，拿到真实 threadId 才操作；结果未知先核实，不能重复创建。
按工具要求展示会话入口，并做必要的一次有界等待取得初始进展，不能把创建成功当作交付。
不要为配置切换改全局 config.toml。当前任务子代理与长期员工会话不同，不固定增设监督代理。

## 接收交付

员工提交最终输出后，经理直接核对所引用的差异和证据，作出接纳或返工决定。
长期员工使用`wait_threads`接收完成结果；不要把可由工具读取的交付交给用户搬运。

恢复或用户要求查看已完成交付时，使用一次`wait_threads(timeoutMs: 0)`紧凑快照；
需要正文才`read_thread`最近交付。在途任务用工具允许的有界`wait_threads`并携带cursor，
子代理用有界`wait_agent`；等待超时后继续等待完成事件，不轮询日志、索取进度或自动重派。
用户新指令先按其边界处理。未来调度按SKILL.md的授权与恢复规则执行。

## 修订和取消

在原活动索引标明有效版本及失效动作，向已授权员工发具体变更。
取消、缩减权限或更换执行者时，确认受影响写入已停止，后台任务已终态或唯一监督明确且不争用新任务资源，
再放行冲突动作；不影响独立的已授权工作。不笼统杀进程或重启业务操作。
投递成功、聊天结束或归档不能单独证明停止。迟到输出保留证据，不覆盖当前任务状态。

缺少会话工具时，生成简短任务由用户手动转交，沿用同一交付格式，不另建监控流程。
