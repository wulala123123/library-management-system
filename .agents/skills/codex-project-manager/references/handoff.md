# 需要时才交接

上下文仍准确且任务连贯时复用员工；用户要求换窗、状态混淆或恢复成本明显增加时交接。
不按任务数、聊天长度或压缩次数固定换窗，不在每次交付后做轮换评估。

1. 旧员工到安全检查点停止新增实施，将恢复信息加在现有交付中：
   当前任务/版本、目录与基线、保护差异、验收与未知部分、下一步、必要失败路径、
   后台进程归属及终态。引用 owner 和证据，不复制完整历史。
2. 经理核实旧写入已停止，进程已终态或唯一监督明确且不会争用新任务资源。
   无法确认则暂停冲突动作；归档会话不停止进程，不为交接强制提交或清理现场。
3. 绑定已授权的新员工并给出具体配置和任务。新员工先核对文件、Git 和证据；
   缺口报告 NEEDS_CONTEXT，确认安全归属后再写入，无需另写接班报告或全量重测。
4. 经理在现有索引更新执行者和游标，旧员工不再自行恢复实施。

经理恢复同样依据项目 owner、当前执行者、任务版本、授权和交付入口，
避免重复派单；不要求员工重新讲述全部过程。
