# 图书馆项目接入

仅在实际管理本项目时读。讨论、导入或修改技能只处理技能产物，不自动启动当前业务任务。

## 启动与状态

从目标工作目录读取 [AGENTS](../../../../AGENTS.md)、[PROJECT](../../../../PROJECT.md)、[PLAN](../../../../PLAN.md)和 [WORKFLOW](../../../../WORKFLOW.md)。按 PLAN 定位当前阶段，核对分支、基线及已有差异。

经理维护 PLAN 的执行游标；任务编号、完整定义及勾选状态由[活动计划](../../../../docs/plans/README.md)路由的阶段文件维护。员工只改派发范围内的实现、必要规范和验收证据。复用现有任务和交付位置，不增加独立员工台账。

若本批使用员工，经理在 PLAN 的当前工作项中记录任务有效版本、执行者身份、文件边界、实际配置或不可核实项，以及交付入口和下一动作。并行任务各有明确写入范围，共享数据升级和状态更新由经理协调。

## 验收与数据边界

- 按[测试与发布检查](../../../../docs/development/testing.md)选择必要验证，复用与当前候选一致的有效证据；技能导入和编辑不运行业务回归。
- 阶段验收按任务定义和适用[领域规范](../../../../docs/specs/README.md)，测试通过不代表会员业务规则已确认或线上已启用。
- 真实会员、宝宝资料、财务快照、密码散列及令牌不进入工单正文、公开交付、Git 或 CI。日志和原始 JSON 放项目忽略的 `logs/`，交付只引用必要结论和受保护证据入口。
- 库存、金额、计次、数据修正和上线权限遵守项目规则。经理或员工身份不增加真实数据与服务器操作授权。
- 项目没有固定的 QuantProject 专用审查代理。按实际风险进行定向只读验收，缺少可用审查能力时说明限制。

新建独立员工会话、联系其他会话和后台调度分别按用户授权及工具约束执行。当前任务内的实施子任务按[会话适配](codex-threads.md)派发，并在交付后由经理同轮验收。
