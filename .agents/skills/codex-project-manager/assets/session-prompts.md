# 可直接填写的提示

只复制所需段落，将方括号替换为实际值。新任务按 SKILL.md 解析并应用具体配置；
这些文字本身不会更改模型或授予跨会话权限。

## 用户启动经理

```text
使用 $codex-project-manager 管理 [项目绝对路径] 的 [目标与边界]。
经理配置：[具体模型/强度及来源]。
员工安排：[已授权联系的实际会话 ID/host 与派发范围；是否明确允许创建新会话]。
按项目启动协议恢复。派单后由员工独立实施，经理同轮等待交付，不例行监督过程。
收到交付直接验收，必要时返工并继续等待；更新项目状态后汇报，不要求我搬运材料或催验收。
若我保留最终验收权，请先完成技术核验和交付整理，再交我验收，不能替我决定业务采用。
范围内工作自主推进；确需我的业务或权限决定时列明具体问题。
```

## 经理派给员工

```text
完成 [任务 ID / 有效版本]。
目标与验收：[内容]。范围与 owner：[路径、职责和保护范围]。
现场：[绝对目录、分支/基线、已有差异及恢复入口]。
本次配置：[具体模型/强度及来源]。
你并非代码库唯一参与者，保留已有改动。按项目协议执行，自行验证和管理进程。
无需例行进度汇报。完成后一次输出：结论、变化、验证与证据、未决与下一步。
证据保存：[仅填写项目要求的现有入口]。关键缺口说明影响与所需决定，不扩大权限。
```

## 必要时交接

```text
旧员工：在 [安全边界] 停止新增实施，输出恢复游标、实际差异、证据、未决和进程状态；
保留现场，交付后不自行恢复写入。
新员工：依据 [交付与 owner 入口] 核对现场；有冲突报告 NEEDS_CONTEXT。
旧写入与进程归属已确认后，在经理派发的范围内继续。无需复制旧聊天或重跑全部测试。
```
